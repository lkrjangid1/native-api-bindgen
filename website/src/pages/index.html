Use Native APIs Directly.

Generate the Binding. Not the Boilerplate.

Automatically generate typed Android and iOS native API bindings for Flutter and React Native. native-api-bindgen reads the Android SDK (android.jar) and the Xcode SDK headers on your machine and writes Dart (Flutter) and TypeScript (React Native) bindings — no hand-written plugin per API, no copied SDK files.

Get Started View on GitHub Read Documentation
Experimental. All four combinations (Flutter and React Native, on Android and iOS) work end to end and are tested on an Android emulator and an iOS simulator — not yet on physical devices. Generated APIs, configuration and output may still change. See what has been tested.

The problem

Using a platform API that the framework does not expose usually means writing and maintaining glue code by hand:

  • MethodChannel handlers and their Dart counterparts, one per API,
  • JNI boilerplate and Objective-C wrappers,
  • TurboModule specs and native implementations for React Native,
  • thread hopping between the UI thread and the framework's thread,
  • and keeping all of it in step with new Android and iOS versions.

The solution

SDK → parser → IR → generator → native binding

Android SDK → class-file parser → IR → Dart over package:jni
                                     ↓
                                     TypeScript over JSI + C++ (JNI)

Apple SDK → libclang + Swift symbol graph → IR → Dart over package:objective_c
                                               ↓
                                               TypeScript over JSI + Objective-C++

Bindings are generated from the official SDKs installed on your machine, typed with nullability, availability and threading from the SDK metadata. Calls go straight to the platform (JNI, objc_msgSend / NSInvocation) — no serialization. See the architecture.

Flutter on Android

Dart extension types over package:jni; generics, bean properties, typed @IntDef constants; Java interfaces implemented in Dart; Kotlin suspend as Future and Flow as Stream. Details

Flutter on iOS

Dart over package:objective_c; structs, NSError **, availability and main-actor checks, blocks; Swift-only APIs through generated @objc adapters. Details

React Native

New Architecture: TypeScript over one pure C++ Turbo Module and JSI, backed by JNI or Objective-C++; Promises for suspend functions, blocks and protocols implemented in JavaScript. Details

Example

// Dart (Flutter, Android)
final intent = Intent.new$String$Uri(Intent.ACTION_VIEW.toJString(), Uri.parse('https://example.com'.toJString()));

// Dart (Flutter, iOS)
final name = ios.UIDevice.currentDevice.systemName.toDartString(); // 'iOS'

// TypeScript (React Native)
const view = UIView.alloc().initWithFrame({origin: {x: 0, y: 0}, size: {width: 10, height: 10}});

Legal and source policy

Official sources first; no private or hidden APIs (non-SDK Android APIs and private Objective-C selectors are never generated); no SDK files are copied, downloaded or published; generated bindings stay in your project by default. See Legal.

Roadmap (future work, not available yet)
