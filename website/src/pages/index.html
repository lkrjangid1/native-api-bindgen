Call Android and iOS platform APIs from Flutter and React Native — generated, typed, local

native-api-bindgen reads the Android SDK (android.jar) and the Xcode SDK headers on your machine and generates typed bindings: Dart for Flutter, TypeScript for React Native. No hand-written plugin per API, no copied SDK files.

Experimental. Vertical slices work end to end and are tested on an Android emulator and an iOS simulator. Generated APIs, configuration and output may still change. See what has been tested.

Flutter on Android

Dart extension types over package:jni; Java interfaces implemented in Dart; Kotlin suspend as Future. Details

Flutter on iOS

Dart over package:objective_c; structs, NSError **, availability guards; Swift-only APIs through generated @objc adapters. Details

React Native

New Architecture: TypeScript classes over one pure C++ Turbo Module and JSI, backed by JNI or Objective-C++. Details

Example

# native_api_bindgen.yaml lists what you need, then:
dart run native_api_bindgen generate flutter      # Android → Dart
dart run native_api_bindgen generate ios          # iOS → Dart
dart run native_api_bindgen generate react-native # Android + iOS → TypeScript
// Dart (Flutter, Android)
final intent = Intent.new$String$Uri(Intent.ACTION_VIEW.toJString(), Uri.parse('https://example.com'.toJString()));

// Dart (Flutter, iOS)
final name = ios.UIDevice.currentDevice.systemName.toDartString(); // 'iOS'

// TypeScript (React Native)
const view = UIView.alloc().initWithFrame({origin: {x: 0, y: 0}, size: {width: 10, height: 10}});

Measured, not promised

  • One Android API used in a Flutter release APK: {{size.flutter.one_api_slice_apk}} bytes, identical whether bindings were generated for one API or the whole SDK (unused bindings are tree-shaken). Baseline app: {{size.flutter.baseline_apk}} bytes.
  • A generated JNI call from Dart: about {{perf.flutter_android.jni_call_us}} µs on an Android emulator (profile mode), versus about {{perf.flutter_android.methodchannel_us}} µs for an equivalent hand-written MethodChannel round trip.
  • All numbers, methods and conditions: Compatibility and the benchmark files in the repository (docs/benchmarks).

What it does not do

  • No private or hidden APIs: non-SDK Android APIs and private Objective-C selectors are never generated.
  • No SDK files are copied, downloaded or published; generated bindings stay in your project by default.
  • No native UI embedding yet, and not every API shape is supported — everything skipped has a reason code.
